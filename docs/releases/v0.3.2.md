# v0.3.2

Release date: 2026-08-01
Release state: final

This patch release covers the `long-horizon-engineering` and
`ai-video-production` Skills distributed through the Codex plugin and
repository marketplace metadata.

## Status

v0.3.2 is the stable patch successor to v0.3.1. It corrects installation and
upgrade guidance, makes full-validation timeout handling deterministic, and
records the current support and repository-security-observability boundaries.

The final package contract is coherent at `0.3.2`: plugin and both Skill
versions match, both update channels and release manifests are `stable`, the
manifests are released and reviewed, and the repository marketplace uses the
immutable `v0.3.2` ref with `policy.installation: AVAILABLE`.

Those fields are package truth for the immutable release commit. They do not
substitute for candidate-bound formal evidence, the remote annotated tag and
peeled tree, GitHub Release publication, isolated marketplace/CLI resolution,
or installed-versus-canonical verification. Each remains an ordered release
gate.

## Patch Scope

- Codex user-level direct installation now consistently uses
  `$HOME/.codex/skills/`; the legacy `$HOME/.agents/skills/` layout is not
  presented as the current user-level default.
- Stable installation and comparison examples use `v0.3.2`. Comparison
  instructions require resolving and recording the annotated tag's peeled
  commit instead of embedding a self-referential future merge SHA.
- Full validation converts subprocess timeouts into deterministic exit code
  `124` diagnostics and gives full unittest discovery a bounded 300-second
  budget while retaining the default 120-second command budget.
- The v0.2.5 maintenance line is retired after v0.3.1 publication and
  replacement-install verification. Exceptional retired-line changes still
  require separate support, review, release, and installation decisions.
- Current disabled or unavailable GitHub security-observability controls are
  recorded as a gap, not as evidence that the source is safe or unsafe.

## Release Boundary

This patch does not add provider or connector runtime, customer-data storage
or upload, account access, retrieval, execution, publication, legal or
financial advice, brokerage, trading, automatic installation, routing, or
authority. Capability cards and the Local Case Evidence Provider remain static,
descriptor-only or default-disabled contracts. The customer remains the only
decision authority.

`ai-video-production` receives metadata alignment only. There is no functional
AI Video payload in this release.

The inherited package still includes the profile-assembly tooling merged by PR
#92. Its default mode is read-only. Explicit `--apply` writes only to an empty
caller-selected output directory outside the source repository; it does not
install or activate a profile, change global configuration, or grant runtime
authority.

## Validation

The authoritative formal inventory contains 23 Draft 2020-12 schemas: 7
schemas have explicit positive and negative instance fixtures and the remaining
16 are explicitly syntax-only. Dependency-free fallback and formal validation
remain separate. The formal gate uses the six hash-locked wheels in
`requirements-release.txt`, performs one approved online acquisition, and
consumes the same raw evidence offline. It does not perform a second live
acquisition.

The final content-frozen v0.3.2 candidate must produce a new formal result
bound to its exact commit, tree, parent/base/merge-base, changed paths, binary
diff, schema inventory, lock, acquisition evidence, pip report, and job
identity. Earlier v0.3.1 or PR receipts cannot be reused.

## Known Limitations

- Static contracts and passing tests do not establish runtime or host
  enforcement.
- Package hashes and publish attestations do not prove reproducible
  source-to-wheel provenance; the reviewed native `rpds-py` wheel limitation
  remains.
- Repository Code Scanning, Dependabot, private vulnerability reporting,
  Secret Scanning, and push protection were disabled or unavailable at the
  2026-08-01 audit. Their enablement is a separate administration decision.
- Marketplace/CLI behavior, GitHub Release state, and installed identity require
  current post-tag evidence.
