## Status

This document describes a Phase A static release-prep candidate with an
operational Phase B formal-schema gate. Routine reviewed PR and `main` CI runs
may execute that gate, but each result is evidence only for the exact candidate
commit, tree, base, diff, and schema inventory it binds. It is not evidence that
a tag, GitHub Release, repository marketplace checkout, installed Skill update,
runtime router, or host-enforced isolation exists. A future release candidate
must produce and independently review its own candidate-bound formal result.
Until then, release-specific formal evidence is PENDING and this candidate is
not release-ready.

The candidate release manifests use `risk: not-assessed`. That value means no
independent release risk disposition has yet been accepted; it is not a
synonym for low risk. Static validation rejects a self-reported `low` value
while the package remains an unreleased candidate.

## Validation Boundary

Phase A may run dependency-free local package, catalog, fresh-copy, unit, and
static pre-tag checks. A successful result means only that the static candidate
is internally consistent. It does not make the candidate release-ready.

Before any tag, Phase B requires separate approval for a temporary CI/release
environment, a hash-locked `requirements-release.txt`, dependency intake, and
formal Draft 2020-12 schema validation. Marketplace isolation, remote tag
resolution, GitHub Release creation, and any installed update remain separate
approval and evidence stages.

The temporary gate is restricted to CPython 3.11 on GitHub-hosted
`ubuntu-24.04` x86_64. It installs only six reviewed wheels with exact hashes,
`--only-binary=:all:`, and `--require-hashes`; it does not add a Skill or plugin
runtime dependency. Each intake must recheck the selected files' yanked state,
hash, license, dependency metadata, Trusted Publisher attestation, source tag
and license identity, and OSV result.

PyPI publish attestations establish the selected upload identity and artifact
digest. They do not establish source-to-wheel SLSA provenance, reproducible
builds, or project trustworthiness. The native `rpds-py` wheel therefore
remains an explicit, gate-specific supply-chain exception. Dependency-free
fallback checks and the formal engine are run and reported separately; neither
can convert a failure or skip in the other into a pass.

The validator's closed inventory is the authoritative machine representation:
it contains 23 Draft 2020-12 schemas. 7 schemas have explicit positive and
negative instance fixtures in this gate; the remaining 16 are explicitly
syntax-only and record why no approved deterministic instance fixture is
mapped. The capability catalog and local case provider schemas additionally
have dependency-free synthetic fixture contracts, which are not substitutes
for formal instance validation. The fixture-validated set includes
decision-record, promotion, and gate-result authority boundaries. Those
synthetic fixtures test structure and rejection behavior; they do not prove a
real customer decision, gate outcome, promotion, or authority.

All local JSON Pointer references and all permitted cross-schema references
must resolve. Release readiness launches the formal validator directly: a
prewritten PASS receipt is evidence only and cannot authorize the gate. The CI
job performs one approved online acquisition into a job-local temporary
evidence directory. The formal validator then consumes that same raw evidence,
deterministic acquisition receipt, and real pip report offline; it does not
perform a second live acquisition. The formal result binds those evidence
hashes, the exact six artifact identities, candidate commit, tree, base,
parents, changed paths, diff, schema inventory, validator, and lock.
Formal execution requires a clean candidate worktree before and after
validation; staged, unstaged, or untracked content cannot be represented by an
older commit/tree. Pip report URLs are restricted to the official PyPI artifact
host over HTTPS without alternate ports or authority decorations. A job-local
receipt is not a cryptographic signature, source-to-wheel provenance, or
authorization for any later stage.

Routine PR and `main` CI run the formal gate in post-tag-safe
`--allow-existing-tag` mode. Tag absence is checked only by a separately
approved release-candidate `--pre-tag` invocation. Routine CI success does not
transfer to a later commit or authorize a tag. Release-specific formal evidence
remains PENDING until the final reviewed release candidate runs the gate and its
candidate-bound result is independently accepted.

The 11 current optional-scaffold warnings remain visible. Each has a scoped,
machine-reported waiver because the omitted SkillOpt runner and disaster
monitoring files are not bundled capabilities; adding them would introduce new
execution, file-writing, or support surface. Any warning outside that exact
registry fails full validation.

## Rollback

Discard an isolated candidate worktree or revert a reviewed release-prep
commit. No formal result authorizes changing an installed Skill, remote ref,
tag, or release.
