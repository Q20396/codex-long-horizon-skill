# v0.3.0

Release date: 2026-07-27

This candidate covers the `long-horizon-engineering` and
`ai-video-production` Skills distributed through the Codex plugin and
repository marketplace metadata.

## Status

This document describes a Phase A static release-prep candidate with a
separately implemented Phase B formal-schema gate. It is
not evidence that a tag, GitHub Release, repository marketplace checkout,
installed Skill update, runtime router, or host-enforced isolation exists.
Formal Draft 2020-12 schema validation remains UNVERIFIED until the reviewed
Phase B job completes locked dependency intake and the formal gate against the
exact candidate commit/tree. The presence of the gate implementation does not
make this candidate release-ready.

## Release Line

v0.2.5 is an independent updater-only maintenance release branched from
v0.2.4. v0.3.0 begins a new governance and catalog release line from `main`.
It includes updater behavior that was independently verified and already
aligned with `main`; it is not a linear upgrade of the v0.2.5 branch.

## Validation Boundary

Phase A may run dependency-free local package, catalog, fresh-copy, unit, and
static pre-tag checks. A successful result means only that the static candidate
is internally consistent. It does not make the candidate release-ready.

Before any tag, Phase B requires separate approval for a temporary CI/release
environment, a hash-locked `requirements-release.txt`, dependency intake, and
formal Draft 2020-12 schema validation. Marketplace isolation, remote tag
resolution, GitHub Release creation, and any installed update remain separate
approval and evidence stages.

The temporary gate is restricted to CPython 3.11 on GitHub-hosted
`ubuntu-24.04` x86_64. It installs only six reviewed wheels with exact hashes,
`--only-binary=:all:`, and `--require-hashes`; it does not add a Skill or plugin
runtime dependency. Each intake must recheck the selected files' yanked state,
hash, license, dependency metadata, Trusted Publisher attestation, source tag
and license identity, and OSV result.

PyPI publish attestations establish the selected upload identity and artifact
digest. They do not establish source-to-wheel SLSA provenance, reproducible
builds, or project trustworthiness. The native `rpds-py` wheel therefore
remains an explicit, gate-specific supply-chain exception. Dependency-free
fallback checks and the formal engine are run and reported separately; neither
can convert a failure or skip in the other into a pass.

The closed inventory contains 20 Draft 2020-12 schemas. Four schemas have
explicit positive and negative instance fixtures in this gate; the remaining
16 are explicitly syntax-only and record why no approved deterministic
instance fixture is mapped. All local JSON Pointer references and all permitted
cross-schema references must resolve. Release readiness launches the formal
validator directly: a prewritten PASS receipt is evidence only and cannot
authorize the gate. The formal result binds the live-recomputed acquisition
receipt, pip report, exact six artifact identities, candidate commit/tree,
validator, and lock hashes. Formal execution requires a clean candidate
worktree before and after validation; staged, unstaged, or untracked content
cannot be represented by an older commit/tree. Pip report URLs are restricted
to the official PyPI artifact host over HTTPS without alternate ports or
authority decorations.

Routine PR and `main` CI run the formal gate in post-tag-safe
`--allow-existing-tag` mode. Tag absence is checked only by a separately
approved release-candidate `--pre-tag` invocation. These controls remain
PENDING and UNVERIFIED until the approved Phase B environment actually runs
them successfully.

## Rollback

Discard the isolated Phase A worktree or revert a future single reviewed
release-prep commit. No installed Skill, remote ref, tag, or release is changed
by Phase A.
